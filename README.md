# Merchant Resolution Desk

Open-source single-merchant prototype: evidence-backed partial refunds, human approval, lost-response injection, reconciliation, and an audit trail.

## Run locally
Requires Node.js 24. No dependencies or installation needed.

    npm test
    npm run build
    npm start

Open http://127.0.0.1:4311. PORT changes the local port. State persists in ignored `.local/desk.sqlite`. Hosting configuration is intentionally omitted. The default mode uses fictional orders, deterministic rules and simulated payment receipts. It does not call live AI or PayPal.

## Demo
1. Select EX-1042 and Analyze case. Missing pouch: $34; delivered items are excluded.
2. Leave Simulate lost response checked, select Review & approve, then confirm.
3. The simulated processor commits once; the response is lost. Select Reconcile refund.
4. Replay same approval proves duplicate suppression with one ledger operation.
5. EX-1044 contains a customer prompt-injection attempt; it cannot inflate the $24 proposal or bypass approval.
6. EX-1045 is outside the 30-day policy and blocks execution.
7. Reset demo starts another demo session without deleting the prior ledger. It cannot release a sandbox operation.

## Optional PayPal sandbox
No credentials, accounts or grants were created. No real sandbox transaction was performed. The adapter is implemented and mock-contract-tested, not live-verified.

Use existing sandbox business credentials after operator authorization. Configure PAYPAL_CLIENT_ID and PAYPAL_CLIENT_SECRET server-side, PAYPAL_SANDBOX_ENABLED=true, and PAYPAL_SANDBOX_CAPTURE_MAP such as {"EX-1042":"sandbox-capture-id"}. The capture must be USD and match the fixture total: EX-1042 $198, EX-1043 $96, EX-1044 $120. Never map production captures or real customer information. The adapter hardcodes api-m.sandbox.paypal.com with no live endpoint option.

See .env.example. Do not commit secrets or use NEXT_PUBLIC_ variables. For local configuration use a secret manager or node --env-file=/private/path scripts/dev-native.mjs. Configuration alone does not verify connectivity.

## Optional AI
An existing OPENAI_API_KEY enables explanation-only calls; OPENAI_MODEL defaults to gpt-4.1-mini. Customer text is untrusted data. AI output cannot change approved amounts, policy or execution. Provider errors disclose deterministic fallback. The adapter is unconfigured and has not been tested against a live AI provider; the default is deterministic.

## Safety and limitations
- Server recomputes policy and requires exact approved amount.
- Unique durable operation claim precedes payment execution. Concurrent requests reuse it.
- Sandbox case keys are global and survive browser changes and demo resets. This intentionally permits one refund per fixture case.
- Original capture ID, exact provider payload, amount and request ID are frozen before the first attempt. Changes to configuration cannot alter retry payloads.
- Known refund IDs use read-only status. Unknown outcomes retry only the same request, with a conservative 24-hour local safety window; older unknowns require manual reconciliation.
- PayPal endpoint-specific idempotency retention still applies. This is not an unconditional exactly-once guarantee.
- Keep the application owner-private and single-tenant. The sandbox ledger is shared across sessions for deduplication. Public/multi-user use requires authentication, merchant authorization, tenant isolation, rate limiting and audit access controls.
- Fixtures are not real fulfillment integrations. No signed webhooks, outbox worker, webhook backfill or production monitoring is included. Audit is durable, not tamper-proof.

## Verification
12 automated tests cover: policy math, prompt injection, claim window, approval/amount validation, concurrency, lost-response reconciliation, cross-session sandbox duplicates, immutable retry payload/capture, old retry window, sandbox adapter contracts, API errors/origin checks and reset isolation.

Rendered mobile, keyboard, zoom and visual QA have not been verified. Native dialogs, semantic buttons, visible focus, responsive CSS, and empty/error/reset states are implemented; they are not certified accessible.
